## Findings

### P2-1. HTML-format text parts are unsanitised, and the preview inlines them as safe

- `src/formwork/text.py:91-99` (`_checked_html`); `preview.html.j2:38`
  (`{{ part.html | safe }}`) and the claim at `:1` ("no script");
  `tests/test_preview.py:144-150`.
- `text_to_html` refuses raw tags on the markdown path but passes any body
  whose first non-blank character is `<`, or that carries `format: html`,
  through verbatim: `<script>alert(1)</script>`, `<img src=x onerror=...>`,
  `<a href="javascript:...">`, `<img src="https://tracker/...">`. The only
  checks are `data-sp-` and `<div` balance. That HTML lands in two places:
  the canvas (where SharePoint's text web part is the only sanitiser), and
  the preview, where it is marked safe and executes when the operator opens
  the file. The template's "no SharePoint, no network, no script" holds for
  the template's own bytes only, and `test_standalone_document_makes_no_calls`
  asserts `"<script" not in html` for a spec that happens not to contain one.
- The spec is operator-authored, so this is a trust-boundary statement, not a
  remote hole. It is P2 because the markdown path was built with exactly the
  rigour the HTML path lacks, the docstrings do not say HTML is trusted, and
  "preview before apply" invites opening a spec someone else wrote.
- Fix: either refuse in `_checked_html` what the markdown path refuses
  (`<script`, `<style`, `<iframe`, `on\w+=` attributes, `javascript:` and
  `data:` in `href`/`src`, `<!--`), matching the existing `data-sp-` refusal
  style; or state in `text.py` and the README that `format: html` is trusted
  input and drop the "no script" claim from the preview template. Either way,
  add a test with a `<script>` HTML part so the property is pinned.

### P2-2. The persisted block of the last text control always carries the page wrapper's `</div>`

- `src/formwork/templates/discover.js.j2:168-169` (`stored.split(CONTROL_OPEN)`),
  `:116-123` (the requested block); `src/formwork/catalogue.py:35-47`
  ("verbatim"); the fixture at `tests/test_dsl.py:59-99` models
  `persisted == requested`.
- The canvas is `"<div>" + blocks + "</div>"`. Splitting on the control-open
  string gives the last element everything to the end of the string, so the
  final block's `canvas` is the requested block plus the wrapper's closing
  tag. The two text controls are placed after every web part, so the second
  sample is always the last control on the page: `persisted` and `requested`
  can never be equal for it, even when SharePoint stores the canvas byte for
  byte. Sample 1 is unaffected. The same split rule in `canvas.py` has the
  same property, and `test_text_part_compiles_to_a_control_type_4_control`
  even documents it ("The last control's body also carries the page
  wrapper's own close"), but the probe's contract ("as SharePoint persisted
  them, matched by control id") does not.
- Consequence: the first live run reports one of two samples as changed, and
  whoever reads it has to work out that the diff is the probe's own artefact
  before trusting the rest. This is the measurement the milestone hinges on.
- Fix: strip a single trailing `</div>` from the last block when the stored
  canvas ends with one (and record that it did), or place the text controls
  before the web parts so neither is last, or have the Python side compare
  after normalising the trailing wrapper. Regenerate the golden and extend
  the fixture so `persisted` for the last sample carries the extra close.

### P2-3. `compile` emits text controls against any catalogue and never reads the measurement the catalogue carries

- `src/formwork/dsl.py:223-254` (`_text_control`), `:261-297`
  (`compile_page`); `src/formwork/catalogue.py:53` (`text_controls`, unused
  by any compiler path); `apply.js.j2:51-58` (byte-exact check throws after
  the page is created); README "Compile" paragraph.
- The catalogue now carries `TextControlSample` pairs precisely so "the shape
  the compiler emits can be checked against a measurement rather than a
  guess" (`catalogue.py:12-14`), and `compile_page` has the catalogue in
  hand, yet it compiles text parts identically whether the catalogue has a
  persisted sample, has none, or predates the probe. An operator can run
  `formwork compile` with a text part today against last week's discovery
  document, paste the apply script, and if SharePoint normalises the text
  control at all, the script creates the page, MERGEs the canvas, and then
  throws `canvas mismatch` with the page left in place. The README says the
  persisted shape "has not yet been read from a live site"; it does not say
  what happens if you apply anyway.
- Fix (small): in `compile_page`, when a spec has a text part and
  `cat.text_controls` has no sample with `persisted is not None`, refuse
  with a `DslError` that says to run `gen discover` first; once the
  measurement is folded in, that check becomes "persisted matches requested
  (modulo P2-2)". At minimum, print a warning from `_cmd_compile` and say in
  the README that apply will abort after page creation on any mismatch.

### P3-1. Markdown: four inputs are silently reshaped rather than refused

- `src/formwork/text.py:49-53` (`_STRONG`, `_EM`), `:125-137`
  (`_block_to_html`), `:48` (`_LINK`).
- `***x***` and `**a *b** c*` produce mis-nested HTML
  (`<strong><em>x</strong></em>`): `_EM` runs over the `<strong>` tags
  `_STRONG` just wrote and its lazy `.+?` matches across `</strong>`.
  Browsers repair it, but "nothing is silently dropped or guessed" is
  violated and the canvas carries invalid nesting.
- `[t](url "title")` does not match `_LINK` (space in the url group) and is
  emitted as literal text, brackets and all.
- `# ` (heading marker, empty title) yields `<h1></h1>`.
- A heading or list item that is not the first line of its block
  (`text\n# heading`, `text\n- item`) is flattened into the paragraph. The
  docstring only promises to refuse a heading that is first with lines after
  it.
- Fix: refuse `*` immediately inside a generated tag (or check nesting after
  the passes), refuse a `[...](... ...)` shape, refuse an empty heading, and
  refuse `#`/`- `/`1. ` on a non-first line of a paragraph block. All are
  one-line checks in the existing `_REFUSED` style.

### P3-2. NUL placeholder collision: `\x00N\x00` in the source is a traceback or a duplicated link

- `src/formwork/text.py:54` (`_PLACEHOLDER`), `:167`, `:175`.
- Links are held as `\x00<index>\x00` and substituted back after the
  emphasis passes. A body containing a literal NUL, digit, NUL (YAML
  `"\x000\x00"`) with no links raises `IndexError` from `links[0]` (a
  traceback, not a `DslError`); with a link present it duplicates the link.
  Pathological, but the task of this module is to refuse rather than guess,
  and NUL should never reach the canvas anyway.
- Fix: refuse any C0 control character other than `\t`/`\n`/`\r` at the top
  of `text_to_html`, which also closes the same input on the HTML path.

### P3-3. `_checked_html` protects the canvas wrapper only against unbalanced `<div>`

- `src/formwork/text.py:91-99`.
- `"data-sp-" in body` is case-sensitive; `DATA-SP-RTE=""` passes and HTML
  attributes are case-insensitive. An unclosed `<!--`, `<style>`,
  `<textarea>` or `<script>` swallows the wrapper's `</div></div>` and, in
  the preview, the rest of the document; none is refused. `<div` also
  matches `<divider>`-style text, which is harmless but shows the check is
  a substring count rather than a tag check.
- Fix: lowercase before the `data-sp-` test; refuse `<!--` without `-->` and
  the raw-text elements (or refuse them outright under P2-1).

### P3-4. `_text_controls` is not tolerant of a scalar under `requested`/`persisted`

- `src/formwork/catalogue.py:117`, `:121`; `tests/test_dsl.py:145-148`.
- `raw.get("requested") or []` returns the value unchanged when it is a
  truthy non-iterable (`1`, `true`), and the `for` then raises `TypeError`.
  The docstring says "never an error"; the test covers a string and a list
  with a bad element but not a number or bool.
- Fix: `if not isinstance(items, list): items = []` for both keys; add the
  two cases to `test_malformed_text_controls_are_tolerated`.

### P3-5. The preview shows hidden and extension components as resolved

- `src/formwork/preview.py:83-92`; `preview.html.j2:46-48`.
- `_preview_part` calls `resolve_component` but not `_check_placeable`, so a
  hidden component or a type-2 extension in the catalogue previews as a
  normal titled card with `resolved=True`, while `compile` refuses it. The
  docstring's "a name the catalogue lacks is shown as unresolved rather than
  refused" is honoured; a name the catalogue has but will not place is not
  marked at all.
- Fix: run `_check_placeable` inside the same `suppress(DslError)` and mark
  the card, with the reason, the way "not in the discovery catalogue" is
  marked.

### P3-6. Refusals reach the operator as tracebacks

- `src/formwork/cli.py:271-275` (`main` has no error boundary);
  `_cmd_compile` `:131-153`, `_cmd_preview` `:118-128`.
- Every `DslError` (and the `TextError` it wraps, and `ValueError` from
  `parse_discovery`) propagates out of `main` as a Python traceback. The
  library-level refusal is clean, as the task asked; the CLI-level one is
  not. Pre-existing pattern for the compile path, but text refusals with line
  numbers are the new everyday case and are designed to be read by a person.
- Fix: catch `DslError`/`ValueError` in `main`, print `error: {exc}` to
  stderr, return 1; one test per command.

### P3-7. `placements.placedCount` excludes the two text controls; `storedControlCount` includes them

- `src/formwork/templates/discover.js.j2:205`, `:208`; golden
  `discover.js:390`, `:393`.
- `placedCount` is `controls.length` (web parts only); `storedControlCount`
  counts every `data-sp-canvascontrol` in the stored canvas. A reader
  comparing the two now sees a two-control discrepancy on every run. Nothing
  in Python reads either field today.
- Fix: `placedCount: controls.length + textControls.length`, or add
  `textPlacedCount`.

## Not findings, recorded so they are not re-raised

- **The four Jinja citation comments sit at the top of `_prelude.js.j2`,
  not at point of use** as the plan wording had it; the JS comments at each
  point of use carry the same citations and are what the tests pin. In
  scope as delivered.
- **`controlIndex` is per section, not per column** (`dsl.py:59`,
  `:164`), while the probe numbers per column (`discover.js.j2:31-38`).
  Pre-existing on `main` for component parts; text parts inherit it. Worth
  reconciling when the persisted positions are read, because the probe and
  the compiler will disagree on what the number means.
- **The compiler writes `1000.0`/`1.0` floats where the probe writes
  `1000`/`1`** (`dsl.py:160-168` vs `discover.js.j2:78-85`). Pre-existing;
  it will show as noise in any requested-vs-compiled comparison.
- **`//evil.example/x` passes `_href_allowed` as relative.** Protocol-relative
  is schemeless by the docstring's definition; not a script vector.
- **Regex cost.** `_EM`, `_STRONG` and `_LINK` are quadratic on a
  pathological line (many unmatched `*` or `[`), not exponential; a
  30k-character line costs seconds. Text parts are page prose; no action.
- **CI's node gate checks extract and apply only** (`ci.yml:56`); the
  discover script's new JS is covered by `TestDiscoverScript` when node is
  present, which it is on both runners. Pre-existing, outside the range.
- **M1 items not in this range**: section headings, vertical sections, and
  "applied byte-exact on the sandbox" from the plan's M1 deliverable. The
  dispatcher's scope statement omits them; noted only so the plan is not
  read as complete.
