## Findings

### P2-1. The model's docstring and its test cite `discovery.m5.json` for a `controlIndex` convention the fixture contradicts

- `src/formwork/dsl.py:403-407` (`section_tree` docstring): "A placement's
  `control_index` counts within its SECTION, not its column: that is the
  controlIndex the M5 probe wrote and read back unchanged for both split
  orders (discovery.m5.json layoutVariants, 2026-09-07), so the tree keeps
  it."
- The probe numbers per COLUMN, not per section. `_probe_legs.js.j2:213-219`
  (`perCol[col] = (perCol[col] || 0) + 1`) and the discover spread at
  `discover.js.j2:26-40` (`perColumn` keyed `"section:col"`). The fixture
  rows the docstring names bear this out: `split-4-8-two-col2` and
  `split-4-8-two-col1` are both `sectionIndex 19` and both `controlIndex 1`
  (`tests/fixtures/discovery.m5.json:4128-4163`). Per-section numbering
  would have read 1 then 2.
- `tests/test_sections.py:143-170` then asserts `(ordinal, column,
  control_index) == [(1, 2, 1), (2, 1, 2), (3, 2, 3)]` under the comment
  "The split-4-8-two measurement … controlIndex per section
  (discovery.m5.json layoutVariants, labels split-4-8-two-col2 then
  split-4-8-two-col1)". The measurement it names has (col 2 → 1, col 1 → 1).
- This is not a regression: `control_index=p_index` is unchanged from
  `feat/provenance`, and the M1/M2 review already recorded it as a
  divergence "worth reconciling when the persisted positions are read,
  because the probe and the compiler will disagree on what the number
  means" (`.hermes/review/2026-09-06_m12-review.md:288-292`). M9 is the
  slice that reads the positions into one model, and instead of
  reconciling it stamps the divergence as measured. FINDINGS.md's
  `page.layout.factors-4-8` claim (`:51`) is about written ORDER being
  kept; nothing in the registry measures the numbering.
- Concrete failure it enables: a `type: two` section with one part per
  column compiles column 2's only control at `controlIndex 2`, a position
  no probe ever wrote. Whether the editor accepts, renumbers or reorders it
  on first save is unmeasured, and the next slice (section emphasis via
  SavePage, which writes `position.zoneId` beside these numbers) will
  inherit the citation as fact.
- Fix, minimum for this commit: rewrite the docstring and the test comment
  to say per-section numbering is the compiler's convention, that the probe
  numbers per column, and that the render-side effect is unmeasured (cite
  the m12 note). Fix, proper, as a follow-up with a live measurement: number
  per column in `section_tree` (`len(by_column[column - 1]) + 1` at
  `dsl.py:432-448` already has the count), which changes emitted bytes for
  multi-column specs and so needs its own findings row.

### P3-3. "No behaviour change" is false on two non-golden output paths (both improvements; both should be named)

- **Preview `data-type` for `columns:` sections.** The parent's
  `preview.py` labelled every `columns:` section `"one"`
  (`type_name = section.get("type", "one")`, HEAD~1 `preview.py:72`). Now
  `Section.layout` gives `two-thirds` for `[8, 4]` and `columns` for an
  unnamed set (`sections.py:130-136`, `preview.py:66`). `formwork preview`
  stdout and `PreviewSection.type` change for any spec that uses
  `columns:`. Nothing pre-M9 pinned it (`test_preview.py` SPEC uses
  `type:` only), so no test moved. Name it in the commit.
- **Unmeasured-factor warning count and location.** The parent's
  `compile_page` called `placements()` twice (once for `wants_text`, once
  for the loop), each firing `warnings.warn(..., stacklevel=2)` from a
  distinct line, so under Python's default filter `formwork compile` printed
  the warning twice per unmeasured section (three times with the findings
  registry, via `reliances`). Now `placements` is called once and every
  caller's warning is attributed to `dsl.py:472`, so one line prints. The
  only pin, `test_dsl.py:828-837`, asserts `any(...)`, so nothing notices.
  Benign, but the commit says "no behaviour change".

### P3-4. Test honesty: the evidence pins in `test_sections.py` are weaker than the commit message says

- `tests/test_sections.py:127` `assert EVIDENCE[factors] in m5_document()`
  checks only that a top-level KEY exists (`"layoutVariants" in doc`). It
  would pass if every row in the fixture carried factor 12. The commit
  message's "pins every measured factor set to its discovery.m5.json
  evidence key" is key presence, not a pin. The real fixture pins are
  `test_default_sections_read_back_with_their_named_factors` (`:262-277`,
  reads `storedCanvas` positions) and `section_factor ==
  factors[column - 1]` at `:289` (reads the requested rows, with
  `persisted_matches() is True` carrying it to the stored bytes). Keep
  those; drop or strengthen the EVIDENCE assertion so it reads what it
  claims.
- `:287` `assert variant.factors == LAYOUT_VARIANT_FACTORS[variant.section]`
  is a tautology: `factors` IS that lookup (`catalogue.py:195-197`).
- `(8, 4)` is measured on column 1 only: `split-8-4` placed `columns: [1]`
  (`_probe_legs.js.j2:205`); no control has ever persisted with
  `sectionFactor 4` inside an 8/4 section. FINDINGS.md `:50` says exactly
  that ("its column-1 control"); `Section.measured is True` for `(8, 4)`
  and the `MEASURED_FACTOR_SETS` comment ("only these exact shapes are
  pinned", `sections.py:48-54`) say more. Pre-existing constant; the new
  test now asserts the looser reading.
- New API with test-only consumers: `LayoutVariant.section/column/factors`
  (`catalogue.py:185-197`) and `Section.measured` (`sections.py:138-141`)
  are used nowhere in `src/`; `dsl.py:422` spells the measured predicate

## What held up (attack list, item by item)

1. **Behaviour drift in emitted bytes: none.** Parent `_control_for` built
   `open_tag` with `_escaped` (`json.dumps` default `ensure_ascii=True`),
   then `mark_dirty()`; the dirty render (`canvas.py:142-163`, unchanged)
   replaced BOTH attributes from the dicts with `ensure_ascii=False`
   compact JSON. New `Control.web_part`/`Control.text` (`canvas.py:92-130`)
   encode once with the same `encode_attribute` and render on the non-dirty
   path. Same dicts, same key order (`_position` and the literals at
   `dsl.py:562-621, 664-670` unchanged), same separators, same escape
   order, same body shape (`<div data-sp-webpartdata=… data-sp-htmlproperties=""></div></div>`,
   `<div data-sp-rte="">…</div></div>`), same `<div>…</div>` preamble
   (`dsl.py:757-760`). `test_canvas.py:154-176` pins new-control render ==
   parsed-then-dirtied render. Refusal wording: every `DslError` string is
   unchanged; the unknown-type check deleted from `placements` was
   unreachable (`section_factors` raises first with the same text).
   Goldens: no fixture file in the diff.
2. **Tree fidelity: holds.** `Section.placements` sorts by page ordinal
   (`sections.py:143-147`), so a column-2 part written before a column-1
   part keeps its written position; `written_order` chains sections in
   order; `compile_page` iterates exactly that list (`dsl.py:684, 704`),
   the same order the parent's flat `placed` list had. Pinned for the tree
   at `test_sections.py:143-170` and for compile at `:200-218` (the
   `columns: [8, 4]` column-2 text part the M7 review found preview
   dropping is present in both).
3. **Double-serialisation: none.** `_blocks_match` (`catalogue.py:114-123`)
   folds `&#58;` on BOTH sides and is what `TextControlSample`,
   `PropertySample` and `LayoutVariant` all call; the delegation in
   `TextControlSample.persisted_matches` is logic-identical to the inline
   code it replaced. `_stored_web_part_data` (`:285-303`) decodes the raw
   persisted block once through `Canvas.parse`; the probe's own
   `webPartData` is `webPartDataOf(b.canvas)` from the same bytes
   (`_probe_legs.js.j2:500-502`), and `test_sections.py:306-318` pins the
   two equal on every fixture row. `_persisted_by_id` drops rows whose
   `canvas` is not a string, so `kept["canvas"]` is always a str and the
   `block is None` branch means "no row", matching the test's branch.
   `html.unescape` is single-pass (`&amp;#58;` → literal `&#58;`), so an
   escaped entity inside a title is not decoded twice.
4. **Layering: clean.** `sections.py` and `canvas.py` import nothing from
   the package; `catalogue` → `canvas`, `sections`; `dsl` → `canvas`,
   `catalogue`, `sections`, `text`; `preview`/`findings` → `dsl`,
   `sections`; `multipage` → `dsl`, `findings`, `provenance`. No cycle.
   Import-time work is constants, frozen dataclasses and one compiled
   regex. (Could not execute the import; verified by reading every
   `from .` line.)
5. **Dead code: removed.** `SECTION_FACTORS`, `MEASURED_FACTOR_SETS`,
   `MAX_COLUMNS`, `ROW_SPAN`, `Placement`, `_escaped`, `json` are gone from
   `dsl.py`; `section_factors` and `defaultdict` gone from `preview.py`.
   Every symbol still imported into `dsl.py` is used (`:362, 375,
   432-472`). The one remaining Python restatement of the factor sets is
   `findings.FACTOR_CHECK_IDS` (`findings.py:85-91`), pinned equal to
   `MEASURED_FACTOR_SETS` at `test_findings.py:201`. The JS literals
   (`discover.js.j2` `FACTORS`, `_probe_legs.js.j2` `LAYOUT_SAMPLES`) are
   pinned to the Python tables by `TestScriptsSpeakTheSameFactors`.
   `_fold_colons` stays in the catalogue by design and now spells the
   entity through `COLON_ENTITY`.
6. **Test honesty: mixed.** See P3-4. The honest pins exist; the headline
   EVIDENCE assertion and one tautology sit beside them, and P2-1's
   comment cites the fixture for something it disproves.
